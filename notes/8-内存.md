# 内存

## 内存基本概念

**内存用于存放数据，程序执行前需要先放到内存中才能被 CPU 处理**。

内存由一个个存储单元构成：

- 如果计算机按字节编址，则每个存储单元大小为 1 个字节
- 如果计算机按字编址，则每个存储单元大小为 1 个字

> [!NOTE]
>
> $1G=2^{10}M=2^{20}K=2^{30}$

## 装入

### 为什么需要

在程序经过编译链接执行后，指令指明的是逻辑地址 (相对地址，相对于进程起始位置而言)，如果不将逻辑地址转换为物理地址，就会导致数据存取位置乱套。

![logic2physical](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/logic2physical.png)

### 绝对装入

在编译时如果知道程序将放在内存中哪个位置，编译程序将产生绝对地址的目标代码，装入程序按照相应地址装入程序和数据。

![absoluteloading](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/absoluteloading.png)

缺点：只适用于**单道程序环境**。

### 可重定位装入

将程序装入到内存中适当的连续空间中并对地址进行重定位，将逻辑地址转化为物理地址。

![relocateloading](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/relocateloading.png)

缺点：

- 一个作业在装入内存时，必须分配全部的内存空间
- 作业进入内存后就不能再移动
- 分配的内存空间必须是连续的

### 动态运行时装入

程序被装入内存之后并不会立即将虚拟地址转换为物理地址，而是将地址转换推迟到程序需要真正执行的时候。

![dynamicloading](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/dynamicloading.png)

## 链接

链接的三种方式：

- **静态链接**：在程序运行之前，先将各目标模块及它们所需的库函数连接成一个完整的可执行文件 (装入模块)，之后不再拆开。
- **装入时动态链接**：将各目标模块装入内存时，边装入边链接的方式。
- **运行时动态链接**：在程序执行中需要用到该模块时，才对其进行链接。

## 完整流程

![wholepip](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/wholepip.png)

- 编译：由编译程序将用户源代码编译成若干个目标模块 (将高级语言翻译成机器语言)
- 链接：由链接程序将编译后的目标模块和所需的库函数链接在一起，形成完整的装入模块
- 装入：由装入程序将装入模块载入内存

## 内存空间的分配与回收

### 连续分配管理方式

#### 单一连续分配

在单一连续分配方式中，内存被分为系统区和用户区。

- 系统区位于内存低地址部分，用于存放操作系统相关数据
- 用户区位于内存高地址部分，用于存放用户进程相关数据

> [!NOTE]
>
> 内存中只能有一道用户程序，独占整个用户区空间。

优点：

- 实现简单，不用采取内存保护

缺点：

- 只能用于单用户单任务操作系统
- 有内部碎片，存储器利用率低

![allo1](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/allo1.png)

#### 固定分区分配

将整个用户空间划分为多个固定分区，每个分区中只装入一道作业。

固定分区分配分为**分区大小相等**和**分区大小不等**两种方法。

![allo2](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/allo2.png)

操作系统需要建立一个**分区说明表**来实现各个分区的分配和回收。

每一行对应一个分区，包含分区大小、起始地址、状态。

![ds](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/ds.png)

优点：

- 实现简单，无外部碎片

缺点：

- 会产生内部碎片，内存利用率低

#### 动态分区分配

动态分区分配不会预先划定内存分区，而是在进程装入内存时根据进程大小动态地建立分区。

![allo3](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/allo3.png)

> [!NOTE]
>
> 区别内部碎片和外部碎片：
>
> - 内部碎片：分配给某进程的内存区域中，有些部分没利用上
> - 外部碎片：指内存中的某些空闲分区由于太小而难以利用
>
> ![not](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/not.png)

- 首次适应算法 (First Fit, FF)：每次都从第一个分区开始找
- 循环首次适应算法 (Next Fit, NF)：从上一个停止的分区的下一个开始找
- 最佳适应算法 (Best Fit, BF)：所有满足的空闲分区里采用最小的
- 最坏适应算法 (Worst Fit, WF)：所有满足的空闲分区里采用最大的
- 快速适应算法 (Quick Fit, QF)：先将空闲分区根据大小分成不同的桶，然后直接选择适合的桶
- 伙伴系统
- 哈希算法

### 离散分配管理方式

#### 基本分页存储管理

页框：将内存分为一个个大小相等的分区，每个分区就是一个**页框**。每个页框有一个编号，即页框号 (页框号从 0 开始)。

> 页框=页帧=内存块=物理块=物理界面

页面：将进程的逻辑地址空间也分为与页框大小相等的一个个部分，每个部分成为一个页/页面。每个页面也有一个编号 (称为**页号**，从 0 开始)。

> 操作系统以页框为单位为各个进程分配内存空间，进程的每个页面分别放入一个页框内。进程的页面和内存的页框有一一对应的关系，但是各个页面不必连续存放，可以放到不相邻的页框中。

页表：为了知道进程中页面在内存中页框的存储位置，操作系统要为每个进程创建一个页表。

- 一个进程对应一个页表
- 进程的每个页面对应一个页表项
- 每个页表项由**页号**和**块号**组成
- 页表记录进程页面和实际存放内存块之间的映射关系

> [!NOTE]
>
> **页表中，只有块号需要占用存储空间，页号是隐含的。**

![page](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/page.png)

> [!TIP]
>
> 某系统物理存储大小为 4GB，页面大小为 4KB，则每个页表项至少用多少字节表示？
>
> 内存块大小 = 页面大小 = $4KB=2^2 * 2^{10} B = 2^{12}B$
>
> 物理存储大小 = $4GB = 2^2 * 2^{10} * 2^{10} * 2^{10} B= 2^{32}B$
>
> 则总共有 $\frac{2^{32}}{2^{12}} = 2^{20}$ 个存储块
>
> 则编号范围为 $0 \to 2^{20} - 1$
>
> 需要 20b 即 3B 来表示每个块号
>
> 第 n 个页号的地址：$页表起始地址 + 3 * n$​

$逻辑地址 = [页号, 页内偏移量]$ 

$物理地址 = [块号, 页内偏移量]$ 

访问内存的有效时间：

- 没有快表：$EAT = 2t$
  - 访问一次页表 (在内存中) 得到物理地址，再根据物理地址访问具体内容
- 有快表：$EAT = a(m+t) + (1-a)(m+2t)$
  - 分为快表命中和没命中两种情况

> $m$：查找快表所需时间
>
> $a$：快表命中率
>
> $t$：访问一次内存所需时间

#### 两级页表和多级页表

页表要占用非常大的地址空间，对于一个有 32 位逻辑地址的分页系统，规定页面大小为 4kB ($2^{12}B$)，则每个进程页表的页表项有 1MB ($32 - 12 = 20, 2^{20}B = 1MB$)。

解决方法是用两级页表：

1. 若采用一级页表，如上所示，页表项大小为 1MB
2. 若采用两级页表，假设外层页号有 10 位，外层页内地址也是 10 位，就会极大省略地址空间

![doublepage](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/doublepage.png)

#### 基本分段存储管理

分段：作业的地址空间被划分为若干个段，每个段定义了一组逻辑信息，并有自己的名字和对应的段号。

段表：每个段在表中占一个表项，记录了该段在内存中的起始地址 (基址) 和段的长度。

![seglist](/Users/yzhbradoodrrpurp/Desktop/OS/notes/resources/seglist.png)

分段和分页的区别：

- 页的大小固定且由系统决定，段的大小不固定且由用户程序编写
- 分页的地址是一维的，分段的地址是二维的

#### 段页式存储管理

分段和分页原理的结合，即先将用户程序分成若干个段，再把每个段分成若干个页，并为每一个段赋予一个段名。

### 静/动态地址重定位

地址重定位：**把程序中的逻辑地址转换成实际内存中的物理地址。**

静态地址重定位：在装入时将逻辑地址转换为物理地址。

动态地址重定位：在运行时将逻辑地址转换为物理地址。

静态地址重定位和动态地址重定位的区别：**地址转换发生在什么时候**。

| 内存分配方式 | 地址定位方式   |
| ------------ | -------------- |
| 固定分区分配 | 静态地址重定位 |
| 动态分区分配 | 动态地址重定位 |
| 页式存储管理 | 动态地址重定位 |
| 段式存储管理 | 动态地址重定位 |

## 对换

### 对换的原因

内存中的某些进程由于某事件尚未发生而被阻塞运行，但它却占用了大量的内存空间，甚至有时可能出现在内存中所有进程都被阻塞，而无可运行进程。

### 对换的类型

整体对换：对换以整个进程为单位。

页面对换/分段对换：对换以页/段为单位。

### 对换的目标

在具有对换功能的 OS 中，把磁盘空间分为文件区和对换区：

- 文件区：存放各类文件
- 对换区：存放从内存换出去的进程

对两个区分别的目标：

- 文件区：提高文件存储空间的利用率和文件访问速度
- 对换区：提高进程换入换出速度

### 进程的换入换出

换出：

1. 选择被换出的进程：状态是阻塞的且优先级最低
2. 非共享的进程直接换出，共享的进程换出前必须判断引用计数减 1 后是否为 0，如果为 0 则直接换出，不为 0 则不能换出

换入：

1. 查看 PCB 集合中所有进程的状态，找出就绪但是已经换出的进程
2. 选出其中在磁盘上时间最久的的进程
